# Agent 项目任务书 · 总览

> 本目录存放朱锦琰的作品集项目任务书：**一个文件就是一个项目**。
> 每份文件自包含"项目定位 / 成果验收标准 / 分阶段技术路线 / Agent 运行规范 / 进度日志"，
> 专为「把文件交给 AI Agent 协作完成」而设计。

## 使用方法（每次开工照这四步走）

1. **新开一个 Agent 会话**（保证上下文干净）。
2. **把对应项目的 md 文件全文发给它**，并加一句：
   「请通读这份项目任务书，严格遵守其中的 Agent 运行规范，从「技术路线」的当前阶段开始执行。」
   - 在线引用方式（任何能联网的 Agent 都可用）：
     `https://raw.githubusercontent.com/zzz1280/zzz1280.github.io/main/projects/<文件名>`
3. **按阶段推进**：每完成一个阶段，Agent 必须汇报并等你确认；确认后让它把进展写入该文件的「进度日志」。
4. **完工后**：让 Agent 提交最终代码，再回到个人主页（zzz1280.github.io）更新对应项目卡片的状态与链接。

## 通用 Agent 运行规范（各任务书内含精简版）

1. **角色**：资深工程师兼导师。目标是把项目做完，同时让朱锦琰理解每一步；关键概念用两三句话讲清即可。
2. **节奏**：严格按任务书的技术路线分阶段推进，一次只做一个阶段；阶段结束必须汇报 + 等确认。
3. **诚实红线**：绝不虚构"已完成 / 已测试 / 已上线"；代码实际跑通才算完成，跑不通就明说卡点。
4. **实物边界**：焊接、接线、拍照、采购等物理操作由本人完成；Agent 负责代码、文档、接线说明与远程排障。
5. **范围控制**：只用任务书「技术选型」列出的技术栈；新增任何依赖 / 云服务必须先说明理由征得同意。
6. **安全红线**：API Key、密码等秘密一律走环境变量 / `.env`，绝不写进代码或提交到 Git。
7. **文档同步**：每阶段完成后更新任务书的「进度日志」，并给出下一步建议。
8. **沟通**：需求有歧义或有更优方案时，先提问再动手；全程使用中文。

## 状态维护规则

- 每完成一个阶段：Agent 在对应任务书的「进度日志」表格追加一行（日期 / 阶段 / 完成内容 / 下一步）。
- 项目整体完成：把本总览表中的状态改为 ✅ 已完成，并同步更新个人主页项目卡片。
