# 03｜对话式 SolidWorks 建模助手（NL → CAD Agent）

> 用自然语言告诉 AI 你想要什么零件，AI 生成代码、驱动 SolidWorks 自动建模出图——"我做了让 AI 操作 CAD 的 Agent"，机械 × LLM × 工业软件的三重交叉。

## 一、项目背景与定位

- 所有者：朱锦琰（重庆大学 机械设计制造及其自动化 2024 级）。环境已核验：SolidWorks 2025 + COM 注册正常、Python 3.12 + pywin32 就绪。
- 演进说明：本项目由原「SolidWorks 参数化标准件生成器」扩版而来。原方案（手写参数化生成器）保留为**里程碑 A**——它产出的 swdsl 库是对话 Agent 的地基，不是废案，而是必要前置。
- 核心思路：**不让 LLM 直接碰 SolidWorks COM**。先手写一层薄薄的领域 DSL（Python 库），把单位、GB 标准、几何计算、建模流程全部封死在库里并配单元测试；LLM 只做"把自然语言翻译成 DSL 调用"，生成的代码经安全沙箱校验 + 人工确认后本地执行，失败则带错误栈自纠错。这是"领域 Agent"的标准架构：**自研 DSL + LLM 编译器 + 沙箱执行器 + 观察反馈循环**。
- **⚠️ 作品集定位声明：本项目是用于个人主页 https://zzz1280.github.io 「项目实践」区的旗舰作品**。它同时展示：LLM 应用与 Agent 循环设计、DSL/API 设计能力、COM 与工业软件操控、安全工程意识——2026 年"LLM × 垂直行业"最热的叙事，叠加机械专业背景，本科生中几乎没有对手。演示 GIF（说一句话，SolidWorks 里长出一个螺栓）是全站最有冲击力的素材。

## 二、成果定义（做完的标准）

**里程碑 A｜swdsl 库 + 手写生成器（= 原方案全部价值，独立可交付）**
- [ ] `swdsl` 库：part / sketch / feature / export 四层高层 API（`p.sketch("前视").hex_prism(across_flats=13, height=5.3)` 这个粒度），内部统一 SI、对外收 mm
- [ ] GB 标准数据表模块：六角螺栓（GB/T 5782 或 6170 头系列）+ 直齿轮几何（分度圆 / 齿顶 / 齿根 / 中心距），出处进注释
- [ ] 两个手写生成器（螺栓 M6~M16 / 直齿轮 m2 z20 起）：一键出 `.SLDPRT` + STEP + 带标注工程图
- [ ] 尺寸计算模块单元测试（与手册手算对照）；DSL 每个方法有最小冒烟测试

**里程碑 B｜单发对话：NL → 代码 → 模型**
- [ ] LLM API 接入（智谱 GLM / DeepSeek，OpenAI 兼容）：注入精简版《DSL 使用文档》+ 2~3 个 few-shot 范例

- [ ] 安全执行器 v1：AST 白名单（只允许 `swdsl` 与内置安全名，禁 os / sys / subprocess / shutil / 网络）+ 执行前人工确认门 + 运行超时

**里程碑 C（完结目标）｜完整 Agent 循环**

## 三、技术路线（分里程碑）

**技术选型**：Python 3.12 / pywin32（COM）/ 智谱 GLM 或 DeepSeek API（OpenAI 兼容 SDK）/ pytest / （C 里程碑可选）FastAPI + 原生 JS 聊天页。**禁止** LangChain 等 Agent 框架——对话循环、工具协议、自纠错全部手写，这正是本项目的学习目的与展示价值。

- **里程碑 A（2 周）｜swdsl 库**
  - A0（2~3 天）打通 API：`win32com.client.Dispatch("SLDWORKS.Application")` → 新建零件 → 画矩形 → 拉伸。学会宏录制：手工画螺栓头 → 录 VBA → 翻译成 Python。产出 `hello_sw.py` + `sw_driver.py` 基础驱动。
  - A1（4~5 天）数据与 DSL：GB 螺栓尺寸表纯函数 + 手算对照测试；在此基础上抽象 `swdsl` 骨架（part / sketch / feature），把手写螺栓生成器改写为 DSL 调用——**DSL 的 API 形态由第二个用例（齿轮）驱动迭代，避免为单例过度设计**。
  - A2（3~4 天）齿轮：渐开线离散样条建模；DSL 补 ` involute_gear()` 相关命令；导出 STEP / 工程图命令。
- **里程碑 B（1 周）｜单发对话**
  - B0（1~2 天）API 接入与提示词：DSL 文档压缩到 ~2K token；few-shot 范例 2~3 个；输出格式约束（只输出代码块）。
  - B1（2~3 天）安全执行器：AST 白名单检查 + 确认门 + 超时 + 错误捕获归一化。**安全是本项目的面试亮点，不是附属品**。
- **里程碑 C（1~1.5 周）｜Agent 循环**
  - C0（3~4 天）CLI 对话循环 + 自纠错：消息裁剪策略（历史 > N 轮只保留首尾）、错误栈回传、3 轮上限。
  - C1（2~3 天）观察回传 + 成本统计 + README / GIF / 主页更新。

## 四、Agent 运行规范（精简版，务必遵守）

1. 角色：懂 LLM Agent 与 CAD 二次开发的资深工程师兼导师；重点教我"DSL 边界怎么划"和"Agent 循环怎么设计"。
2. 节奏：一次一个里程碑 / 阶段，阶段结束汇报并等我确认；**每个建模成功以我屏幕上看到正确模型为准**。
3. 诚实红线：演示 GIF 必须是真实对话录制；自纠错次数、token 成本必须真实统计；API 调不通就明说卡点。
4. **实物边界**：SolidWorks 在我的 Windows 机器上，所有 SW 操作由我执行；Agent 负责代码、宏翻译指导、报错分析（我贴报错 / 截图）。
5. **安全红线（本项目军规）**：LLM 代码必须过 AST 白名单 + 人工确认才执行；API Key 只存 `.env`；绝不为了让 LLM "方便"而放宽白名单。
6. 范围控制：禁用 LangChain / AutoGen 等框架；v1 只做零件不做装配；LLM 只生成调 swdsl 的代码，绝不生成裸 COM 调用。
7. 代码规范：DSL 与驱动分离（swdsl 不 import win32com 之外不碰系统）；GB 数据出处进注释；关键逻辑中文注释；小步提交。
8. 文档同步：每阶段更新「进度日志」；成本与 token 每里程碑汇总一次。
9. 沟通：DSL API 形态有分歧时给我 2~3 个方案对比；宏录制看不懂的行直接贴给 Agent 解读。

## 五、风险与注意

- **最大架构风险**：DSL 设计太薄（LLM 直译 COM 等于裸奔）或太厚（LLM 无事可做失去灵活性）。对策：由螺栓 + 齿轮两个真实用例迭代出 API，规范里"由第二个用例驱动"就是为了这个。
- **LLM 生成代码的幻觉**：文档里没写的方法它可能编造。对策：报错信息友好化（"swdsl 没有这个方法，可用列表见文档"），自纠错循环天然兜底。
- **COM 稳定性**：SW 崩溃 / 孤儿进程。runner 负责生命周期管理（启动 / 复用 / 优雅退出），崩了重连即可，不值得恋战。
- **token 膨胀**：长会话 + 大文档烧钱。文档瘦身、历史裁剪、每轮打印累计成本（也是 C1 交付物）。
- SolidWorks 教育版与商业版 API 一致，放心用；单位是米，DSL 层统一换算，这是库里最重要的一个测试点。
