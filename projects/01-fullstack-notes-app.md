## 三、技术路线（分阶段）

**技术选型**：Python 3.11+ / Flask 3 / Flask-Login / SQLAlchemy（或 sqlite3 参数化查询）/ SQLite / Jinja2 模板 + 少量原生 JavaScript / Chart.js（加分项）。
> 选型理由：Flask 轻、资料多、与我的 Python 主线一致；不上前端框架，保持"看得到每一行代码"的学习价值。

- **阶段 0｜现状盘点（0.5 天）**：Agent 的第一件事——让我完整描述 / 提交当前已有代码，输出"已完成清单 + 问题清单 + 剩余任务列表"，重新排定后续阶段。已开工的项目必须先做这步。
- **阶段 1｜数据模型与用户系统（3~4 天）**：User / Note 表设计 → 注册登录登出 → 密码哈希（werkzeug）→ 登录保护装饰器。产出：能注册登录的最小版本。
- **阶段 2｜笔记 CRUD（4~5 天）**：列表 / 新建 / 编辑 / 删除 / 完成切换 / 搜索；所有查询按 user_id 过滤。产出：功能完整的核心版本。
- **阶段 3｜前端与体验打磨（3 天）**：页面布局、移动端适配、空状态与错误提示、（加分）统计图。产出：能拿得出手的界面。
- **阶段 4｜部署上线（2 天，可选但强烈建议）**：Render 免费层部署，SQLite 换持久卷或改用免费 Postgres；配置环境变量。
- **阶段 5｜收尾（2 天）**：README、截图 / GIF、提交仓库、更新主页卡片、复盘写一段"我学到了什么"。

## 四、Agent 运行规范（精简版，务必遵守）

1. 角色：资深全栈工程师兼导师；目标是做完 + 我能学会；关键设计决策用两三句话向我解释。
2. 节奏：一次只做一个阶段，阶段结束汇报（做了什么 / 遇到什么 / 下一步），等我确认再继续。
3. 诚实红线：不虚构完成；代码必须实际运行验证；跑不通就明说卡点。
4. 范围控制：只用上述技术栈；加任何新依赖先说明理由征得我同意。
5. 安全红线：SECRET_KEY / 密码等走环境变量；不提交任何秘密进 Git；SQL 一律参数化。
6. 代码规范：关键逻辑中文注释；小步提交，commit 格式 `feat: / fix: / docs:`。
7. 文档同步：每阶段完成把进展追加到「进度日志」。
8. 沟通：有歧义先问我；全程中文。
