## 一、项目背景与定位

- 所有者：朱锦琰（重庆大学 机械设计制造及其自动化 2024 级）。

- **⚠️ 作品集定位声明：本项目是用于个人主页 https://zzz1280.github.io 「项目实践」区展示的算法 + 前端作品**，纯静态托管（GitHub Pages，与主页同款技术栈，零成本上线）。它补齐我作品集里"CS 基础"这一格，和硬件项目形成"软硬都行"的完整画像。

## 三、技术路线（分阶段）

**技术选型**：原生 HTML / CSS / JavaScript（与个人主页一致，不依赖框架）/ Vitest 或简单自写断言做算法测试 / GitHub Pages 部署。
> 不用 React / Vue：动画的本质是"状态 → 渲染"，原生实现更能体现对渲染循环的控制，也和我的主页技术栈统一。

- **阶段 0｜动画引擎（3 天）**：设计"算法 → 步骤序列 → 播放器"架构：排序算法产出 `[{type:'compare', i, j}, {type:'swap', i, j}...]` 步骤数组，播放器按步骤渲染 + 速度控制 + 单步。先用冒泡排序打通全链路。产出：引擎 + 冒泡排序 demo。
- **阶段 1｜排序全家桶（3~4 天）**：补齐选择 / 插入 / 快速 / 归并（快排注意递归分区的步骤还原）；每种的比较 / 交换计数器。产出：排序模块完成。
- **阶段 2｜网格寻路（4~5 天）**：网格数据结构（墙 / 权重）→ 四种算法同样按"步骤序列"产出访问顺序 → 动画展开 + 路径回溯 + 统计面板。A* 用 Manhattan 启发。产出：寻路模块完成。
- **阶段 3｜UI 与移动端（2~3 天）**：布局、控件样式、响应式、操作提示；性能注意（大数组用 canvas 或减柱数量）。
- **阶段 4｜收尾（2 天）**：部署 Pages、README + GIF、单元测试补全、主页卡片更新。

## 四、Agent 运行规范（精简版，务必遵守）

1. 角色：前端 + 算法双背景的资深工程师兼导师；重点教我"动画引擎与算法解耦"的架构思想（这是本项目的灵魂，比多写一个算法重要）。
2. 节奏：一次一个阶段，阶段结束汇报并等我确认。
3. 诚实红线：动画展示的每一步必须真实对应算法执行状态，严禁"演个大概"；复杂度数字必须与实现的实际行为一致。
4. 范围控制：只用原生三件套；不引入任何前端框架 / 动画库（requestAnimationFrame 手写就够）；不上后端。
5. 代码规范：算法模块（纯逻辑，可测试）与渲染模块（DOM/canvas）分离；算法函数必须有正确性单元测试；关键逻辑中文注释。
6. 文档同步：每阶段更新「进度日志」。
7. 沟通：交互设计（按钮放哪、动画多快）先给 2~3 个方案让我挑，不擅自定稿。

## 五、风险与注意

- 大数组（100+ 根柱子）逐帧改 DOM 会卡：超过 60 根自动切换 canvas 渲染或降低数组规模，阶段 3 处理。
- 递归算法（快排 / DFS）转"步骤序列"时注意还原真实的递归顺序，别偷懒排序结果假装过程。
- 别陷进 UI 细节：先跑通引擎和算法（阶段 0 是灵魂），美化放最后。
