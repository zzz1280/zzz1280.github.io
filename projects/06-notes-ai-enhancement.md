## 三、技术路线（分阶段）

**技术选型**：Python / LLM API（DeepSeek 或智谱等 OpenAI 兼容接口，国内直连便宜）/ Embedding API（同平台）/ SQLite 存向量（列表存 JSON，量小够用）/ 原生 JS。
> 不引入向量数据库（Milvus / FAISS）——几百条笔记用不上，面试时能解释"为什么不用"本身就是加分。

- **阶段 0｜API 准备（0.5 天）**：注册平台、拿 API Key、存 `.env`；用 curl / 最小脚本验证能调通；确认计费价格，设预算上限。
- **阶段 1｜自动摘要 + 标签（3 天）**：保存笔记后异步调用 chat 接口 → 解析返回 → 存库 → 列表页展示；失败重试一次 + 降级。产出：保存笔记自动出摘要和标签。
- **阶段 2｜语义搜索（3~4 天）**：笔记保存时生成 embedding 存库 → 搜索时对查询词做 embedding → 余弦相似度 Top-N → 与关键词搜索并列展示，对比效果差异。
- **阶段 3｜前端整合与降级（2~3 天）**：加载态（"AI 思考中…"）、失败提示、相似笔记推荐（可选）。
- **阶段 4｜收尾（2 天）**：README + GIF、成本与调用统计、主页卡片更新、复盘"调 API 与训模型的区别"。

## 四、Agent 运行规范（精简版，务必遵守）

1. 角色：懂 LLM 应用开发的资深工程师兼导师；重点教我 Prompt 设计与成本意识。
2. 节奏：一次一个阶段，阶段结束汇报并等我确认。
3. 诚实红线：演示的摘要 / 搜索结果必须是真实 API 返回，绝不 mock 假数据冒充效果。
4. **安全红线（本项目的第一条军规）**：API Key 只存 `.env`，`.env` 进 `.gitignore`；代码里严禁出现任何明文 Key；提交前必须检查。
5. 范围控制：只用 OpenAI 兼容接口 + SQLite；不引入向量数据库、LangChain 等重型框架——手写调用与相似度计算是学习目的。
6. 代码规范：API 调用独立成模块（`ai_service.py`），带超时与重试；关键逻辑中文注释。
7. 文档同步：每阶段更新「进度日志」。
8. 沟通：模型选择、Prompt 措辞先给我 2~3 个方案说明利弊再定。
